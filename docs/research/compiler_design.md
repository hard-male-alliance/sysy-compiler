# SysY 2022 → RV64GC LP64D compiler: design and validation research

## Decision context (2026-09-27)

The repository task asks for a complete SysY 2022 compiler, one RISC-V assembly output, and mandatory SSA/optimization. This note complements `docs/architecture/sysy2022-contract.md`; that document is the local source-of-truth summary for language/runtime quirks. External sources below are primary specifications, upstream implementation/documents, and peer-reviewed papers. These findings are design recommendations, not observations of a working compiler in this repository.

## Implementation-critical contracts

| Concern | Evidence | Concrete implication |
| --- | --- | --- |
| LP64D scalar arguments | [Ratified RISC-V psABI, §2.1–2.2](https://docs.riscv.org/reference/abi/v1.0/riscv-cc-procedure-calling-convention.html): integer/pointer arguments use `a0`–`a7`; named float arguments use `fa0`–`fa7` when available, independently of integer register exhaustion; floating return uses `fa0`, integer return uses `a0`. The first overflow argument is at entry `sp+0`; stack is 16-byte aligned at procedure entry and throughout execution. | Maintain **separate** integer and FP argument indices; precompute outgoing stack area; preserve alignment for calls. Test mixed `int`/`float` signatures, >8 of each kind, recursion and nested calls. Array formals are pointer-valued integer-class arguments. |
| Narrow scalars and registers | [psABI §2.1–2.2](https://riscv-non-isa.github.io/riscv-elf-psabi-doc/): RV64 `int` is 32-bit, pointer 64-bit; signed 32-bit arguments are sign-extended to XLEN even when stack-passed; LP64D binary32 arguments in FP registers are NaN-boxed; `s0`–`s11` and `fs0`–`fs11` (up to ABI_FLEN=64) are callee-saved. Variadic arguments follow the **integer** convention, not the named FP convention. | Distinguish i32 arithmetic/storage from 64-bit addresses; do not truncate pointers. For `putf` if implemented, default argument promotion plus variadic integer-class passing is a separate ABI path; the local task supplement says it is optional, so isolate rather than contaminate normal calls. |
| `mem2reg` scope | [LLVM upstream `PromoteMemoryToRegister.cpp`](https://www.llvm.org/doxygen/PromoteMemoryToRegister_8cpp_source.html) promotes only slots used by direct compatible non-volatile loads/stores, places phi nodes using iterated dominance frontiers, then renames in dominator DFS. [Cytron et al., TOPLAS 1991](https://cs.brown.edu/research/pubs/techreports/reports/CS-91-21.html) introduced the dominance-frontier construction and reported usually-linear practical size. | Promote scalar locals whose address does not escape. Do **not** turn whole arrays, array elements with dynamic aliasing, or escaped addresses into independent SSA scalars without proof. Compute CFG reachability/dominators first; phi incoming values must correspond to actual predecessor edges. Use liveness pruning if complexity warrants it, but correct unpruned phi placement is preferable to a buggy shortcut. |
| Short-circuit | Local SysY specification requires C-like short-circuit and logical results 0/1. This is control-flow semantics, not merely a boolean operator spelling. | Lower `&&` and `||` to branches and a join (phi or temporary) so RHS—including calls or faulting operations—is not evaluated when skipped. Make both condition contexts and value contexts (`return a && f()`) use the same lowering rule. Optimizations must not speculate possibly effectful/trapping RHS code across the branch. |
| Array initialization | The local language defines row-major, brace-aligned subaggregates, omitted-element zero fill, and runtime-valued local initializers. | Implement one recursive shape/offset walker over flattened element slots, honoring nested-brace boundaries. Separate shape/layout from expression evaluation: global/const values require constant evaluation; local initializer expressions must retain source order and side effects. Do not treat omitted local-array elements as uninitialized when an initializer is present. |
| Undefined/poison-like behavior | [LLVM IR UB manual](https://llvm.org/docs/UndefinedBehavior.html) shows how careless speculation and branch use of undefined values change program meaning. Local SysY leaves some arithmetic/uninitialized behavior underspecified (see contract note). | Define a conservative optimization policy: fold only when semantics are established; never use host C++ signed overflow or out-of-range float→int as a constant-folding oracle. Avoid importing LLVM `poison` machinery unless the custom IR explicitly defines it. Do not let `-O1` manufacture a new observable side effect or remove a reachable runtime call. |
| RISC-V symbol accesses | [psABI code models/relocations](https://riscv-non-isa.github.io/riscv-elf-psabi-doc/) specify PC-relative `AUIPC` pairs and GOT requirements for PIC. | Prefer assembler pseudoinstructions such as `la`/`call` and toolchain relocation handling unless a code-model requirement forces manual sequences. Emit one target ABI, e.g. `-march=rv64gc -mabi=lp64d`, and verify assembly with the actual cross assembler/linker + bundled runtime archive. Avoid hard-coded absolute addresses. |

## Validation and optimization strategy

1. **Tiered oracle.** Follow [LLVM testing practice](https://llvm.org/docs/TestingGuide.html): cheap unit/regression tests for lexer, parser, semantics, IR and assembly patterns; then whole-program compile–link–execute tests checking stdout, stderr, exit code, and runtime side effects. A generated assembly text check alone cannot establish ABI or behavioral correctness.
2. **Differential optimization tests.** Compare `-O0` with each pass and full `-O1` on defined SysY programs, linking the same runtime. Use targeted programs for short-circuit calls, aliases via array parameters, loop exits, mixed float/int calls, and brace initialization. [Csmith's PLDI 2011 study](https://users.cs.utah.edu/~regehr/papers/pldi11-preprint.pdf) explains why undefined-behavior-free random programs and unusual feature combinations are essential for a trustworthy differential oracle; a SysY-specific generator is needed rather than blindly feeding Csmith's wider C dialect.
3. **Pass invariants.** After every transformation, check terminators, CFG successor/predecessor symmetry, phi arity/incoming edge identity, def-use validity, and dominance. Instrument stage timing and pass counts separately from emitted compiler output. A pass that "works" only on generated happy-path IR is not complete `mem2reg`.
4. **Performance methodology.** [LLVM benchmarking guidance](https://www.llvm.org/docs/Benchmarking.html) calls for repeated measurements, high-resolution clocks and noise control. Record wall time and CPU time by stage, source bytes/tokens/IR instructions/blocks, peak memory, toolchain and machine versions. Track two distributions rather than one average: tiny-file cold process latency (startup, IO and SQLite setup may dominate) and large/long-tail compile throughput. Regressions must be compared against identical output and correctness.

## Research frontier and adoption judgment

| Direction | Actual contribution and limit | Judgment for this project |
| --- | --- | --- |
| Bounded translation validation | [Alive2, PLDI 2021](https://web.ist.utl.pt/nuno.lopes/pubs.php?id=alive2-pldi21) checks LLVM IR transformations using SMT and found dozens of LLVM bugs; loop unrolling bounds mean it can miss bugs, and it assumes LLVM IR semantics. | **Do not claim verified optimizations** for a custom SysY IR. Borrow the idea: validate each pass's input/output with differential E2E tests and explicit IR invariants. An SMT encoding is future research only if ordinary oracles expose unresolved pass bugs. |
| Equality saturation/e-graphs | [`egg`, POPL 2021](https://popl21.sigplan.org/details/POPL-2021-research-papers/23/egg-Fast-and-Extensible-Equality-Saturation) makes rewrite-driven equivalence exploration efficient through rebuilding and e-class analyses. It is not a drop-in solution for side-effecting control flow, aliasing, or target ABI. | **Not on the critical path.** Consider later for bounded, pure scalar expression islands after exact arithmetic/FP rewrite semantics and a cost model are defined. SSA, SCCP/CSE, CFG cleanup and correct lowering offer more direct value now. |

## Open evidence/decision points

- The local task document permits ARM **or** RISC-V; RV64GC LP64D is the team's selected direction supplied in this research assignment, not an obligation of the task document itself.
- Exact `putf` support is optional in the local supplement. If implemented, validate C varargs promotion and ABI with the supplied RISC-V library; normal FP argument logic is insufficient.
- No actual cross-link/E2E measurements or compiler implementation were inspected for this note. Runtime ABI compatibility remains an executable test, not a conclusion from specs alone.
